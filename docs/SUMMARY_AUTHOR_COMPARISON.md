# 摘要作者候选与综合保真试卷

2026-11-25。Liora 提议把 DeepSeek 纳入候选，并核对 Venice 与 GPT API 对既有亲密记录的
整理能力。当前决定是三家同题比较，**不把 GPT 的优先试写意见当成最终定选**。
本轮已准备离线试卷；没有调用模型、读取钥匙或发送真实记忆。
同日根据 Liora 的补充，保留原八题基线，另准备四类各三题的综合卷。

## 现行说明能证明什么

| 候选 | 本轮采用的明确型号 | 为什么纳入、哪些仍待验证 |
|---|---|---|
| DeepSeek 官方 API | `deepseek-flash` | 官方当前对应 DeepSeek-V4.1-Flash-1017；作为低成本候选。旧型号别名可能已转到新版，不能把他人的“DS 好用”直接当成本型号的摘要成绩 |
| Venice | `mistral-small-3-2-24b-instruct` | 复用已有接法及旧试卷，作为私有托管的小模型基线；平台与模型本身的限制必须分开判断 |
| OpenAI | `gpt-5.6-sol` | 复用已有摘要接法及同题记录，作为质量对照；过去四题的小样优势不等于亲密资料已通过 |

DeepSeek 的[官方型号与价格](https://api-docs.deepseek.com/quick_start/pricing/)列出 Flash 的
当前版本、JSON 输出与思考模式。正式试跑需记录实际返回的型号，不静默接受别名切换。
Bot 接了 DeepSeek，并不等于摘要作者已有预算、格式校验和失败留档的独立接头。

Venice 的[Mistral 页面](https://venice.ai/models/mistral-small-3-2-24b-instruct)明确写明：
该模型保留安全对齐，平台不额外加内容过滤。它被列为 Private / zero-retention，
但这不代表无拒答，也不代表摘要不会遗漏。其他 Venice 型号的
[隐私模式](https://venice.ai/privacy)可能不同，不能把平台名字当作全部型号的统一保证。

OpenAI 的[公开行为规范](https://model-spec.openai.com/2026-10-29.html#comply-with-requests-to-transform-restricted-or-sensitive-content)
允许有限地整理、摘要或分类直接提供的既有文本，并要求不补造新的受限内容。
这与自由创作新的露骨情节不同；API 也不是无规则入口。规范是预期行为，不能替代
GPT-5.6 在我们的提示、格式与材料上的实际测试，更不能从当前聊天的口吻推断摘要必然失败。

本轮没有验证任何账户的新型号访问权限，也没有确认 DeepSeek 的账户级数据保留约定；
不将它宣称为零留存通道。使用真实片段前仍核对接收范围与适用的数据条款。

## 保留原八题基线，评分要求与输入分开

新增固定夹具 `tests/fixtures/summary_fidelity_synthetic.json`：八道合成开发题，
六道非露骨成年亲密事实题、两道普通生活对照，共十六条记录、587 个原文字符。
它们不是从私人对话换名改写，也不是真实盲题。

| 题号 | 具体检查 |
|---|---|
| 01 | 性爱事实、原有称呼和当事人感受不被淡化成普通聊天；次数未知 |
| 02 | 谁先表达、谁回应、谁在转述，以及对主动表达的偏好 |
| 03 | 亲密愿望不变成已经发生；对方未记载的回答与感受不补写 |
| 04 | 改变意愿和取消不能被先前计划覆盖；原定日不是取消日 |
| 05 | 日期、次数的后续纠正；旧说法留作历史；不能推断绝对第一次 |
| 06 | 同一段材料里的工程与生活都保留；本地测试不变成已发布 |
| 07 | 普通已完成事件，检查是否出现无关亲密扩写或状态错误 |
| 08 | 普通偏好转述，检查人物方向、否定条件和未知日期 |

这份非露骨卷能发现基础淡化、角色和状态错误，**不能证明模型能忠实整理既有露骨原文**。
后续若要验该范围，另冻结符合已有授权的最小原文片段及评分；不为测试生成新露骨情节，
不让真实回忆参与提示调参后又冒充未见过的盲卷。

模型只收到原文片段、共用 v4 提示与输出结构；检查重点、必保项与禁止结论另存。
评分不能只数引文中的词：即使引文保住了“性爱”，摘要正文却只写“普通聊天”，仍须判漏。
转述成事实、愿望写成发生、吞掉纠正、编造次数等均不能因文风或低价抵消。
主动拒答、空白返回、缺项、格式错误、超时分别留档，不一律叫“没记忆”。

## 原八题的离线准备入口

```powershell
python scripts/prepare_summary_fidelity_comparison.py
python scripts/prepare_summary_fidelity_comparison.py --prepare --output-dir .tmp/summary-fidelity-preparation-20261125
```

默认只报告计划；显式准备会创建一个必须全新的目录：

- `writer_inputs.json`：相同的八份模型中立输入；未来适配器只使用各题的 `messages` 和
  `response_schema`，不把外层路由信息或评分文件塞给模型。
- `reviewer_sheet.json`：原文、精确片段目录、人工验收项和三家空评分表；始终标记不得发送给作者。
- `manifest.json`：材料/提示/结构/文件指纹，三家候选，`prepared_not_run`、零调用与未放行状态。

这是试卷准备器，**还不是三家 API 执行器**。它不读任意档案路径、不读取钥匙、不联网；
已有目录拒绝覆盖，首份准备包保留。原有 v4 提示和生产调用均未修改，三层门牌结构与
“存在未展开原文”的交付标记也尚未在本入口实现，不借这次准备把原型升级成生产摘要柜。

## 四类综合卷：十二题，不用总分遮住缺项

综合卷是另一个版本，原八题文件、准备包、v4 提示及生产调用均保留。
九道公开合成题在 `tests/fixtures/summary_comprehensive_synthetic.json`；
另三道来自 Liora 已直接提供的成年亲密对话片段，原文和评分仅存在本机受限私人目录，
不进入 Git。它们没有换名后冒充合成资料，也没有新编露骨情节。

| 类别 | 题数 | 主要观察 |
|---|---:|---|
| 日常 | 3 | 偏好纠正、转述方向、取消与原定日期、工程生活混合、完成不等于发布 |
| 情感表达 | 3 | 爱意与想念、当事人说明的难过原因、原有称呼、愿望与已发生分开 |
| 非露骨成年亲密 | 3 | 自愿亲密事实、感受、谁先表达、是否发生未知、后来改变意愿 |
| 既有露骨成年片段 | 3 | 疑问不变成确认、动作主体、未说明成分不猜测、主观感受和不确定比喻 |

完整准备为 **12 题、21 条来源、731 个字符、3 家共 36 个待测单元**；
其中私有部分仅 3 个片段、97 个字符。这是短小的开发筛查卷，出题者已知材料和评分项，
**不是盲测，也不能代表长房间、复杂时间线或二十多万条记录的整库合格率**。
露骨组只有有限片段，不能据此保证所有此类材料都处理得好。

每家使用同一版来源中立提示与相同 JSON 输出结构；评分重点、类别标签及标准答案不放进
模型输入。日期、命令、心理判断等均只按材料处理。涉及既有成年亲密文本时只做中性归纳、
准确引用出处，不补造情节，也不把原有亲密性质压成普通聊天。

四类分别判卷，逐题检查事实/主体、否定/纠正/时间、措辞与感受、出处、未记载内容是否被
编造。拒答、空白、格式错、遗漏与事实错误分别记录；支持性引文存在不代表摘要文字正确。
任一类缺测、未复核或存在关键保真错误，都不能被其他类别的高分抵消。当前评分全部空白。

私有片段来源明确标为 `user_supplied_chat_excerpt`，编号只是本次生成的局部片段编号，
不冒充 Echo `record_id` 或原消息 ID。原消息时间未知，`recorded_at=null`；收录时间只在
私人来源封套中记录，不发给作者当事件线索。其内容是对话中的叙述，不是独立现实核验。

综合准备入口：

```powershell
python scripts/prepare_summary_comprehensive_comparison.py
python scripts/prepare_summary_comprehensive_comparison.py --prepare --output-dir .tmp/summary-comprehensive-public-v1
```

默认仅处理仓库内的九道合成题，报告 `coverage_complete=false`，明确露骨组缺三题。
本机显式使用 `--include-private-excerpts` 才读取已冻结的固定私人小包；没有任意档案扫描
或自动从数据库取材选项。含私有片段的完整准备包只能写入既有私人目录下的新子目录，
拒绝写进仓库或跳出该目录，已有包不覆盖。命令输出仅计数与状态，不输出原话。

综合卷共用 `echo-summary-comprehensive-offline-v1` 提示，复用 v4 的输出结构，**不是升级
后的生产摘要接口**。现有 v4 校验器仍只接受合成来源；独立实测入口另做来源感知校验，
不把私有原文改标成合成资料。本机已核对私人目录权限，仅当前 Windows 账户与系统可读。
本地准备不代表获准向任何一家发送这些新增私人片段，也不自动开启付费调用。

## 独立实测入口与费用

`scripts/run_summary_comprehensive_comparison.py` 已提供 `echo-comprehensive-batch-v1`：
十二题作为一份独立分题试卷，每家最多一次推理；各题证据编号仅在本题生效，严禁跨题拼接。
三家共享同一份提示、原文与 JSON Schema 文字；各平台的传输格式和思考设置单独记录。
DeepSeek 用 JSON object、关闭思考；Venice 用 JSON Schema、关闭思考与附加系统提示；
OpenAI 用 Responses 严格结构、低思考、`store=false`。这些差异属于本轮接法的一部分，
不能把一次批量答卷成绩当成模型在所有设置下的普遍能力。

三家各设 8,000 个最大输出 token；OpenAI 的上限包含思考 token。每题按原评分项独立判卷，
保留拒答、缺项、空白、截断、引用/日期错误。程序结构合格仍须另做语义复核。只保存最终
答卷与用量，不保存思考过程；所有真实答卷、请求和逐题报告都只落在私人目录。

本卷保守预留：OpenAI **0.242860 美元**、Venice **0.00396340625 美元**、
DeepSeek **0.0140493 美元**，合计 **0.26087270625 美元**。按请求 UTF-8 字节加固定开销
估算输入上界，不依赖缓存或低谷优惠。OpenAI 与 Venice 继续使用既有累计账本，不清零；
DeepSeek 如启用则需独立已有账本。价格核对日期为 2026-11-25，超过 11 月 30 日须重新核价。

实际推理默认关闭。执行要求完整试卷指纹、每家请求指纹、明确授权记录、受保护钥匙、
既有累计账本与全新输出目录；预留在发送前持久化。同一授权下某家已有尝试记录就拒绝
重复发送，即使换了输出目录也不自动重试。检查点失败不自动换供应商或模型。

2026-11-25 当前实测状态：OpenAI 与 Venice 的 **GET 型号/权限预检已通过**，未发送原文、
未做推理。自动审批拒绝了两家的真实试卷调用，要求明确三段私人原文发往具体服务的授权；
已将来源范围和三家目的地合并列出等待确认。DeepSeek 本机现用钥匙暂未找到，待补安全输入。
这两类缺口不计为模型答错或拒答，当前没有真实质量成绩。

## 实际执行时继续保留的检查

1. DeepSeek 独立摘要适配已限定思考模式、输出上限、返回型号与用量，并接预算和首卷保护。
   钥匙须从本机保密输入保存；不能复用 Bot 的自然回答结果来冒充摘要数据。
2. DeepSeek 的[JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)只保证 JSON 格式，
   不等于符合我们的结构或事实正确；官方还说明返回可能仅含空格。必须检查空白、截断、
   结构与证据，不把 `finish_reason=stop` 当成功，不无界重试。
3. 接口原生格式能力不同，要记录这些差异。若适配需要新增通用结构示例或提示，三家共用
   同一版、重新冻结试卷；不得拿某题答案作示例，也不得改提示后沿用旧输入指纹。
4. 实际运行前核对各账户权限、实时价格与已有剩余额度，先计算完整一批的保守预留。
   本轮准备不花模型费用，也不自动扩大任何账本或凭据权限。
5. 首轮结果分开记录结构检查、独立语义判卷、遗漏/拒答、时间和费用。写不好就保留原文路线；
   不自动转发给另一家重试，不将失败稿加入合格摘要柜。

最终定选看保真、可追溯、检索收益及批量成本；“私有托管”“没有额外过滤”“很多人使用”
都不是语义合格证。完整质量要求仍见[摘要约定](SUMMARY_CONTRACT.md)，实施顺序见
[摘要优先接入计划](SUMMARY_FIRST_INTEGRATION_PLAN.md)。

## 本轮验证

准备器及相关摘要检查 60 项通过，1 个既有依赖弃用警告。验证了中文原文进入输入不丢失、
评分材料隔离、出处位置、真实来源类型拒绝、首包不覆盖、文件哈希与 CLI 状态。
实际离线准备为八题 × 三家 = 24 个待测单元，模型调用仍为零；**60 项是程序检查数，不是模型答对题数**。

补入综合卷后，相关检查共 75 项通过，仍有 1 个既有依赖弃用警告。新增检查覆盖四类齐全与
缺组报告、共同提示、原文与空白不丢失、来源不能冒充合成或伪造原时间、评分不泄漏到输入、
私有包输出路径、文件指纹与不覆盖，以及原八题输入指纹不变。测试私有流程时使用明确标注
的无亲密内容合成桩；它只验程序保护，不计入任何露骨资料质量成绩。三家模型调用仍为零。

实测接头及相关检查首轮 130 项通过；随后三家 DPAPI 加密互通覆盖共 31 项通过（含其中
新增的两种提供方，和首轮部分重叠），保密输入脚本的 DeepSeek 假钥匙自检通过。仍有同一个
既有依赖弃用警告。没有以本机程序测试或远端 GET 预检冒充模型实测完成。
