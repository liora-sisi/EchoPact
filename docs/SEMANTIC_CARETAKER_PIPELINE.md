## 这次接好了什么

`backend/memory/semantic_caretaker_pipeline.py` 的 `SemanticCaretaker` 固定数据库、
调用身份及源库指纹。调用者只显式注入三个模型回调，不能由模型换库或改身份。

```text
原问只读检索 → 原始回退包
  → 确定性约束检查：日期/来源/先后等受限题停在原路线
  → 规划模型：只读问句，至多两个追加词面查询
  → 本机混合检索一次；单主题比较问题可复用至多两次对象补查
  → 本机合并有界窗口目录，给初选模型至多十二张卡
  → 初选只圈编号，补齐选中记录已找到的其他窗口与已知冲突方
  → 核对原始分支位置，按需补邻文
  → 复核模型选择逐字原文，本机校验与短包封装
  → 仅 brief 给接收方；完整 audit 留在本机
```

旧的 `caretaker_pipeline.py` 和正式入口没有改接新模块。
本节没有预写摘要、生成回答、写真实库、额外模型下载或新供应商依赖。

多路候选先按路线轮流取卡，按记录、偏移、长度和全文指纹去重。
本机完整目录最多六十张，模型初选仍最多十二张、最多圈两张。
如果同一条消息的补充窗口排在初选清单外，圈中该消息后会从**已找到的目录**中补回；
不会以此名义重新无限搜索。相同原文的略有重叠窗口不强行拼接或改写。

补回过程不得丢失已选窗口、改变问题或引入未选且无已知冲突关系的记录。
冲突闭包超过两条根记录、补回超过容量或邻文无法完整装入时，退回完整原候选的未审预览。
各路线此前已有的遗漏、对象扫描到顶及跳过组仍传入最终限制，不因后段说“足够”就消失。

## 总上限与回退

| 项目 | 上限或约定 |
|---|---|
| 模型调用 | 规划、初选、复核各一次，共三次，无自动重试 |
| 外层召回操作 | 词面至多三次、混合一次、对象至多两次，共六次 |
| 模型材料 | 初选/复核各十二张、每张四百字符、每次 24,000 UTF-8 字节 |
| 最终证据包 | 12,000 UTF-8 字节；原文出处与限制一并计算 |
| 等待预算 | 默认 120 秒，在阶段边界检查；可下调到至少一秒 |
| 身份与源库 | 每个边界复核源库指纹和当前身份；变化后拒绝旧结果 |
| 钱 | 核心不带支付客户端；试验驱动按每次实际 payload 先预留，再调用 |

“六次召回”是外层操作计数，**不是六条 SQL**。一次混合操作内还会调用词面检索，
索引不可用时会再次核对身份后走词面回退；原文展开和邻文校验也有各自有界读取。
`trace.hybrid_status` 保留真实是否使用了向量，不能把索引失效回退算向量成功。

120 秒是停止开启下一步骤的预算，**不能强制中断已经阻塞的回调**。
既有 API 传输另有 60 秒网络超时；核心不承诺整个调用精确在 120 秒内返回。
模型请求的系统提示和 schema 也产生费用，不能只按卡片大小估价。

无规划、受限题或规划失败保留原问回退包。多路材料矛盾、前段取证失败、总操作预算耗尽
亦回原问；初选/复核失败使用合并目录的未审预览，完整原问与各路线仍在本机审计。
源库或授权改变则失败关闭，不能退回已失效的材料。第一次原问都取不到时只报固定错误，
不编造回退结果，也不抄出异常正文。

当前 v2 中，契约有效的 `needs_clue` / `no_rewrite` 允许一次原问混合检索；
不生成追加关键词，不触发对象补查。`needs_clue` 在最终包保留并强制提示仍需证据。
它与规划缺席、失败、非法输出或确定性约束不等同。

## 首次真实调用，严格 2/3

固定试卷 `tests/fixtures/semantic_pipeline_exam.json`：十五条虚构记录，三道开发题，
另有两道日期/来源约束对照。问句、原文、预期、实现、索引和模型指纹在调用前冻结。
使用已下载的 BGE-small-zh-v1.5 与既有 GPT-5.6 通道。

本次**没有预置命中记录、命中偏移或参考规划**：模型先读原问，实际 SQLite 检索与
本机向量产生候选，后两阶段请求由已验证的前段结果派生。发送前核对固定虚构原文白名单；
标准答案与评分标签不进数据库或模型请求。没有真实记忆外发。

| 开发题 | 首次结果与证据 |
|---|---|
| 名称像颜色，实际颜色相反 | 通过。保留真实颜色及杯底标记，没有按名称猜颜色；对象补查实际执行一次 |
| 换说法问收纳，邻文撤销旧方案 | 通过。词面路线没找到两条目标，混合候选找到两条；更正做法与小零件条件都保住，旧方案仅作上下文 |
| 安排撤销，尚无替代安排 | **未通过**。目标不在词面/混合前十，选中旧安排后从邻文补回撤销原句；未把旧方案当答案，但把“还没定”标为 sufficient/none，而预设要求 insufficient/missing_answer |

第三题不是漏召回或伪造安排，而是**回答未定状态与提供具体安排之间的充分性判定分歧**。
“还没定”本身可以回答状态问题，本题预先要求的是具体安排；不能凭结果倒改标准算通过。
保留首次答卷，后续应以成对的“问状态/问具体安排”题检验契约和模型行为，必要时同时调整
问题定义与指令。未将其直接归咎于向量，也未新增关键词补丁或重考刷分。

本节还没有让接收方模型根据证据生成自由回答，不能把目标可见算成接收方理解正确。
这三题是开发小样，不是盲测、生产准确率或真实复杂生活旧题的修复证明。

九次实际调用，无重试；每题三次模型调用，外层召回为五、四、四次。
三个最终包分别 **2,442 / 2,717 / 2,415 字节**；本机计时约 **9.9 / 12.3 / 15.0 秒**，
不包括模型首次加载和预检，不能推广为生产延迟保证。所有包仍带覆盖限制与待核验标记。
两道约束对照均零模型、一次原问检索；这只验证绕过新路线，不表示日期题已经答对。
