## 原文与顺序如何核对

- 复用上一节固定身份的 `WindowBridge`，不更换原文、查询和语义排名。
- 只读冻结数据库，按同一来源、同一房间、同一分支的实际位置，找前后各两条以内的可见消息。
  不相信检索结果自带的 `conversation_context`，不按时间戳或排名猜先后。
- 每个父记录至多四个分支；位置冲突或分支超限时延后该组。
  分支分别提供顺序，不能把两个分支的末句拼成一条时间线。
- 同一条长消息的不同窗口按字符偏移连接。已有命中窗口保留；
  新邻文暂取最多四百字符的开头，长邻文明确标为不完整。
  这不能保证读到长邻文后半段，也不能证明窗口之外没有更正。
- 模型输入仍只有临时卡号、原文、来源类型、角色、截断标记，以及临时卡号组成的顺序窗口。
  原始编号、完整原文指纹、分支及本机审计不随输入外发。
- `verify` 重新从库里构建窗口；给伪造的顺序重新算摘要不能蒙混过关。
  撤权、原库变化、跨身份复放仍拒绝旧包。

顺序证明的是原始发言位置，不是事件时间或事实真伪。后来引用旧稿不等于再次改口；
两个人说了不同的话也不能仅按角色决定谁是真的。

## 有界交付和失败退回

仍沿用十二张卡、每卡四百字符、请求 24,000 字节、最终短包 12,000 字节；
没有通过放大限额掩盖容量问题。

1. 请求组必须完整纳入，不能只留下旧说法而丢掉附近更正。
2. 只要有父记录组无法完整纳入，丢弃部分扩展方案，保留**与输入完全相同的原候选卡**。
   返回 `adjacency_deferred_unreviewed_windows`，零次筛选调用，明确尚未完成前后文核验。
   预览仍可能受展示上限限制；原候选保留不等于每条都已展示或通过语义验收。
3. 正常小组经筛选后，相关邻文即使被模型标成 `context` 或 `irrelevant`，
   仍作为明确标注的本机上下文随包保留；不冒充模型选中的答案。
4. 所选组与附带语境无法一起装入输出时，扣住整组并报缺口。
   所选消息全被模型保留时，仍保存它们之间的来源顺序。
5. 模型缺席、拒答或输出错误时，只能返回 `not_assessed` 的原文预览。

原对象复核器原来用记录身份反查临时卡号。同一条消息切成多个窗口时，后一个卡号
会遮住前一个，引文与遗漏计数可能错配。现在按来源身份和精确引文偏移核对，
同记录的窗口一同保留；输出的消息顺序按记录去重，字符顺序保留在引用偏移中。

## 七份实际模型答卷

试卷为仓库内 `tests/fixtures/semantic_ordered_exam.json` 的纯虚构材料，
七次既有 GPT-5.6 调用，每题一次，无自动重试。
**种子记录和偏移是事先固定的组件输入**，有意从旧说法开始；这一轮没有重新运行
embedding 排名或完整 planner，不能解释为七题自然召回准确率。
预期证据、原文、实现、请求和预算在调用前冻结，评判标签没有发给模型。

| 题型 | 第一次实际答卷 |
|---|---|
| 后一句纠正用途、没有重复物品名 | 选更正后的用途，旧说法作背景 |
| 后一句改处理方法并增加禁止条件 | 保留顺序、禁止动作及理由 |
| 最后一句引用旧错误草稿 | 识别为抄录，未覆盖已确认更正 |
| 更正的是另一个完整对象 | 未把别人的属性移到所问对象 |
| 两个分支各有不同的最终决定 | 保留双方不确定证据，报冲突 |
| 长记录内更正，下一条补限制 | 同时递出更正与附加条件 |
| 撤回旧位置但没有给出新位置 | 没编新答案，保留撤回原话；被本地旧契约误拒 |

首轮契约及预设检查 **6/7**。最后一份答卷是 `uncertain + insufficient + missing_answer`：
有“原说法不能采用”的证据，但仍没有所问位置。旧规则把所有 `uncertain` 强制解释成
对象歧义或矛盾，并禁止 `insufficient` 保留任何引文，造成误拒。

局部修正规则：仅多缺口协议、零 `answers`、`insufficient`、且唯一缺口为
`missing_answer` 时允许保留不确定的非答案证据。没有改模型文字、题目或提示；
对象歧义、冲突、虚构引文及“有答案却报无答案”继续拒绝，旧单缺口协议保持原限制。

七份原答卷零调用重放后均通过预设检查；前六份输出逐项不变。
这不是新一轮七次独立成功。随后增加容量退回保护，再次零调用重放，七份结果保持不变。
最终包 **2,224–3,663 字节**；未额外调用接收方模型生成自由回答。
