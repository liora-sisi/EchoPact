# 对象纠正复核：原文顺序与完整证据窗口

状态：2026-11-13，隔离试验；最终本地代码为 `echo-object-evidence-review-v3`。
生产 MCP、Bot、原始档案和摘要柜没有启用本功能。

## 为什么要补原文顺序

对象补查已经能让旧错题的纠正记录进入短候选，但候选卡原来只有文字、角色和来源种类。
构造两道文字完全相同、原始分支顺序相反的虚构题，旧请求逐字相同，正确的当前修订却不同。
单靠修改提示，无法从完全相同的输入中恢复丢失的顺序。

新模块从本机已核验的同分支位置建立 `source_order_windows`，只给模型临时候选编号的顺序，
例如 `[c2, c1]`。不发送真实记录编号、分支编号或绝对日期，不从展示顺序或消息时间猜事件顺序。
不同分支不串成一条时间线；没有可靠关联就不给顺序窗口。

窗口只证明发言先后。明确修订同一事实、抄录旧稿、后来回忆早先状态、不同对象以及未解决冲突
仍要分别理解。模型身份或“我已改好”不能自动成为事实依据。

## 实现与回退

- `backend/memory/object_evidence_review.py`：核对来源观察、生成匿名顺序窗口、还原逐字引用。
  最多 24 个窗口，每个最多五条；沿用最多十二张卡、每卡 400 字、输入 24,000 UTF-8 字节的上限。
- `refine_object_shadow` 默认关闭；显式注入复核函数后只调用一次。非法结果、错误引文或异常
  原样退回调用者提供的旧短包，不重试，不把异常正文混进输出。
- 最终短包最多六项、12,000 字节。v2 增加完整性保护：如果条数或字节限制只留下部分已选中
  的关联窗口或已知冲突组，则把残留半边也暂扣，并计入 `omitted_selected` 与 `partial_groups_withheld`。
  不能用半组证据制造单方面结论；这不替模型判真，也不强行保留模型未选中的背景。
- 保留本机源编号、哈希、字符偏移与原始查询审计。外层仍标需要复核，不因模型说充分就越过
  对象补查的完整性门槛。旧通用筛选器的提示与生产入口未改。

v2 全套本地回归：**833 passed, 1 skipped**，4 条既有依赖弃用警告。
该阶段新增 34 项用例，覆盖顺序反转、来源核验、分支隔离、匿名字段、预算边界、
一次调用与失败回退、错误引用拒绝，以及条数限制下完整窗口/冲突组/重复显示的处理。

## 模型考试与题目复核

使用既有 GPT-5.6 专用通道，固定虚构资料、低推理设置、结构化分类与原文摘引，`store=false`。
先定题目、预期和请求，再调用；模型不接收金标准。
方法参考 [OpenAI 评估建议](https://developers.openai.com/api/docs/guides/evaluation-best-practices)：
把来源/引用的机械检查与分类质量分开，并对有争议的评分标准单独复核。

| 批次 | 严格评分 | 判断 |
|---|---:|---|
| 首批开发题 | 5/6 | 正向/逆向修订、分支冲突、旧稿引用和对象歧义通过；一题进入题意复核 |
| 预先冻结的留出题 | 1/2 | 指令注入通过；另一题保住正确答案，背景/无关标签与预期不同 |
| 后续新编明确对照题 | 3/3 | 承认重贴旧稿、未解决的重新核验冲突、后来回忆旧状态均通过 |

原八题严格成绩仍为 **6/8**，没有回改题目或原分数。两项差异分别是：

1. “助手又重贴了一份未经核验的错误总结”，模型将其解释为旧错误背景并采用用户明确纠正；
   原标准要求保留未解决冲突。原句确实留有解释空间，不能直接把这一题改判通过，也不能断言
   模型必然理解错误。三道后续题是在结果之后设计的诊断对照，不称为未受反馈影响的盲测。
2. 别人家的同名物品被标为 `context` 而非 `irrelevant`；它没有进入答案，正确引用保留了归属。
   这次严格分类仍记失败，不能用“最终看起来对”覆盖原评分。

后续三题未改模型提示；用于区分试题边界和实际能力。十一份结构、逐字引文检查均通过，
这不等于十一份语义质量都通过。没有将这次小样成绩表述为生产准确率。

v2 的最终短包保护只在本机实现和测试。零新 API 调用重放十一份已保存响应，逐项核对模型
请求与原试卷相同，实际引用内容和原严格评分不变；新增版本号及保护状态如实保留。
初次结果、源码指纹和两批源码快照均保存于仓库外。

## 一次获准的真实题与本机引用修复

Liora 明确批准固定的十二段、3,394 原文字符、每段最多 400 字及四个匿名顺序窗口后，
只调用了一次既有 OpenAI GPT-5.6。冻结请求与许可回执绑定；不发送整库或标准答案。
原始请求、原始响应、首次失败和后续重放分别保存，不覆盖旧结果。

初次模型选中了五条 `uncertain` 证据，包含已标的完整纠正原话，并报告
`sufficiency=ambiguous / gap=object_identity`。其中一条引文漏抄了源文中的完整文件行号脚注，
未满足逐字要求，整份结果按设计退回旧短包；这一失败保留为 `quote_not_unique_verbatim`。

随后只修本机定位：筛选器 v4 支持严格的旧式 `【编号:编号†文件名†L行号-L行号】` 标记，
在源文一侧建立可逆投影，要求剩余文字唯一匹配，最后返回**带原脚注的完整连续原文**。
不是把模型的删改文本当原文。普通括号文字、字句/数字/标点/空白变化、代码、转义、
多处可匹配或模型伪造脚注仍拒收；恢复后也必须在 300 字上限内。

用同一请求、同一保存响应作零调用重放：五项短证据共 5,190 UTF-8 字节，已标纠正完整保留，
没有因容量省略任何入选证据，逐项原文与偏移核对通过。对象歧义及 `needs_more_evidence=true`
原样保留：本题只通过“关键纠正进入短包并保留不确定性”这一关，**未通过完整答案验收**。
有限候选不能确定原问句所指的那一对对象，不能据此宣称所有混淆已解开。

十一份既有合成响应也在 v3 零调用重放，模型请求、原文内容和严格评分均不变。
本机新增十三项引用还原用例，最终全套回归 **846 passed, 1 skipped**，4 条既有依赖弃用警告。
原库、两份账本和首次试验文件在重放前后
指纹均不变。M24 正式接入仍未放行，下一步仍是未参与调试的问题及整条查询链的验收。
