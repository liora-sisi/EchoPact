## 比较什么

`backend/memory/caretaker_evaluation.py` 在召回结束后读取人工标过的目标片段，
这些目标不进入规划器、检索参数或模型候选请求。分别记录：

- 原问首次完整结果是否包含已核原话，包括邻接上下文。
- 当前 MCP `detail=brief` 的目录是否含可展开的目标编号，预览是否已显示目标。
- 查找管家最终短包是否保留目标原话，引用的来源、房间、说话人、记录时间及字符位置是否正确。
- 相对原始首次结果新增或丢失哪些已核片段，以及三种返回包各有多少 UTF-8 字节。
- 模型自报充分度、系统缺口和人工复核结论，三者分开。

短目录直接来自同题 `detail=brief` 调用，不是把已经截断的完整包再压一次。
编号能展开但预览没显示答案，不算检索丢失；编号正确但引文、位置或出处错误，也不算通过。
空白金标准保持 `unscored`。单个目标片段命中只能证明这句在场，不能证明整题答全。
未标注的其他记录不能自动算作干扰项。验收器始终输出 `release_eligible=false`，不代替人工放行。

## 固定六问的离线结果

语料、身份、参考时间和代码指纹固定；两道已调试旧题各有一个部分目标，
另外两道是同一事实的新问法，最后两道只验约束保留。
这不是新事实的独立盲测，也不是全量错题库验收。

| 问题类别 | 原始首次结果 / 当前目录 | 离线整链结果 | 当前目录 / 管家短包字节 |
|---|---|---|---:|
| 旧物品比较题 | 目标均未出现 | 精确重放旧回复后，纠正原话保留；对象歧义仍在 | 9,142 / 5,190 |
| 旧版式约定题 | 目标均未出现 | 精确重放旧回复后，已核版式原话保留 | 10,555 / 2,803 |
| 物品比较的新问法 | 目标均未出现 | 仅冻结候选；没有对应模型回复，保留回退结果，不计模型失败或通过 | 9,797 / 7,377 |
| 版式约定的新问法 | 目标在原始结果和目录中 | 因“之前”回原路线，目标仍在 | 10,437 / 11,647 |
| 日期对照题 | 没有完整人工答案 | 一次原始检索、零模型回调；答案准确性未评分 | 10,636 / 11,315 |
| 指定来源对照题 | 没有完整人工答案 | 一次原始检索、零模型回调；答案准确性未评分 | 9,634 / 7,292 |

只有前两道复用旧模型回复，而且要求本次候选请求与旧请求逐字段完全相等。
新物品问法使用旧主题计划作为本机候选准备假设，不声称新问句已被模型正确理解。
`planner_attempts` 和 `review_attempts` 在离线结果中是回调次数，不是新增 API 调用。

本机逐项核对全部拟递引文的原文位置与出处。两道旧题各找回一个已标片段，
但物品题仍缺准确对象指向；版式题还混有某一批页面的操作安排，不能把该批页数当成永久规则。
旧回复的 `sufficient` 不会覆盖系统 `needs_more_evidence=true`，也不代表整段历史已穷尽。

## 本轮暴露的限制

- “之前”仍属于保守的先后约束线索，因此一部分普通回忆问法不能进入模型路线。
  本轮保留原问与第一次准备中断记录，没有删掉这个词换一道容易通过的题。
  此例原始检索已命中目标，所以这是可用范围限制，不能误报为记忆完全召回失败。
- 小管家回退摘录有时比现行短目录更长。正式接入应保留现行目录作为关闭/受限时的入口，
  不能用“比旧完整包小”代替“比当前方案更好”。
- 时间和来源对照只证明模型没有改变检索路线，不证明原召回的日期或来源理解已经正确。
- 本机结构化错题登记仅见一份未标注旧卡，不能据此声称已审完云端全部错题。
