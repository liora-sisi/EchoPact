# 对象补查：本机多看，仍只递少量证据

状态：2026-11-13，本地影子试验。生产 MCP、Bot、原始数据库和摘要柜没有启用这条路线。

## 已确认的缺口

上一轮真实比较题 A 的已核目标不在筛选器候选中。只把模型换聪明，不能补出它没看到的证据。
本次只读诊断发现三层原因：

1. 目标纠正只提对象名字，没有重复问句的类别词；邻近草稿使用的是同类物品的另一种普通叫法。
2. 类别补查的前十条仍漏掉它。扩大本机诊断范围后，在第 29、30 条候选的相邻对话中找到目标。
3. 相邻的助手草稿本身有混淆；道歉或重写也不自动等于正确。必须保留纠正及相关草稿，继续判断。

人工已知目标只用于诊断与计分，不进入运行时查询、词典、排序或提示。
这道题已参与调试，属于旧错题回归，不能当成全新盲测或整体准确率。

## 当前实现

`backend/memory/object_recall_shadow.py` 只处理问句小管家已验证的**单主题比较问句**。
日期、来源、说话人、否定、原话、最早/最近等限制仍走原路线；多主题、做法题也不在本阶段扩查。

- 显式传入固定身份、只读 runner；没有模型客户端，不读钥匙、不调用 API。
- 最多两次额外本机查询，每次最多 48 条主候选。查询词只有原问的主题及已有公开类别别称。
  复用 `named_collection.public_subject_aliases`；没有新增私人对象名词典。
- 每条最多检查 8,000 字和四条已有前后文。关联要求来源、对话、分支和相对位置吻合，
  相距最多两条；不能因为时间相近就拼接。可见性由固定身份的底层查询在 LIMIT 前过滤。
- 只把类别附近的 `《名称》` 当作可追溯线索，沿同段对话收集含该线索的原文。
  暂不理解任意指代、不做语义同义合并，也不把书名号自动判成正式对象名。
- 带有纠正用语的用户记录提高**人工复核优先级**，不自动覆盖助手记录或变成已判定事实。
  同一窗口的入选记录整体装入，不能为了凑最后一个名额只留草稿、丢掉纠正。
- 最终最多 12 段、每段最多 400 字，请求提案最多 24,000 UTF-8 字节，兼容已有证据筛选契约。
  源编号、完整文本指纹、字符偏移、主命中到相邻记录的路径仅留本机。
- 保留旧问句影子结果，另存所有本次查询与原始结果。失败不调用模型、不重试、不替换旧短包；
  错误细节不混进状态。相同源编号出现内容或身份元数据变化时拒绝这批提案。

整个结果始终标记 `needs_more=true` 和对象身份待核。名称附近出现一条记录，并不能证明
它就是问句所指的那两件物品；扫描上限、未展示候选、未知覆盖范围都保留。
扫描结果只用于私有本机审计，不能把完整 `scans` 当作客户端输出。

## 本机真实回归

固定语料、时钟和身份，复用已有问句计划，没有重新请求问句模型。

| 检查 | 结果 |
|---|---|
| 旧错题 A 追加查询 | 2 次，只读本机 |
| 有对象线索的去重记录 | 34 条 |
| 新短候选提案 | 12 条，3,394 原文字符，9,949 UTF-8 字节 |
| 已标目标及完整核验引文 | 从旧提案的 0/1 变为 1/1 |
| 逐条核对权限、来源、原文偏移及完整文本指纹 | 12/12 |
| 未装入提案的线索记录 | 22 条，明确保留缺口 |
| 扫描是否到顶 | 是；不得声称完整历史已查尽 |
| 做法、动作及日期对照 | 不追加对象查询，保留原路线 |
| 原始数据库、两份费用账本 | 前后指纹相同，无 WAL / journal |
| 新增模型调用、真实正文外发 | 均为 0 |

这证明已核目标能进入新候选提案，**没有验证模型会正确选取或解释它**。
也不能把本机 1/1 与上一轮另一题的 1/1 拼成新版本端到端 2/2。
此前批准的 36 段固定模型试卷仍是独立授权；本轮新提案尚未外发。

## 验证与使用

合成测试覆盖未知物品/名称、前十条之外的纠正、无类别词的相邻记录、分支与来源隔离、
权限、日期/否定不扩查、完整窗口的预算截断、字节上限、同编号变化、无名称证据和只读 SQLite。
本阶段新增 32 项用例；最终全套 **799 passed, 1 skipped**，4 条既有依赖弃用警告。

```powershell
python -m pytest tests/test_object_recall_shadow.py tests/test_query_caretaker.py tests/test_evidence_selector.py -q
```

调用仅用于冻结、已核对指纹且无 WAL 的私有离线档案。例中的 `shadow` 是此前本机保存的
问句试验结果，不包含人工答案；不要把私有参数或结果写进仓库。

```python
from backend.memory.object_recall_shadow import readonly_runner, run_object_shadow

result = run_object_shadow(
    shadow, query=original_question, as_of=frozen_reference_time,
    runner=readonly_runner(private_frozen_database, fixed_agent_id),
)
# result['prepared'] 只是本机候选提案；这一调用不会发送给任何模型。
```

完整诊断、初次/最后结果和提案留在仓库外私人验收目录。正式启用前还需：
新对象题与反例、实际筛选器对纠正/歧义的语义复核、整条问句→补查→短证据链验收。
没有开启全量摘要、无限补查、自动扩大模型外发范围或生产发布；M24 门槛不降低。

随后加入的[对象纠正复核](OBJECT_EVIDENCE_REVIEW.md)已完成合成小样及短包完整性保护。
本页真实候选后来获准发送一次：纠正原话进入短证据包，但对象歧义仍在，不能作为完整答案。
初次引用因漏抄来源脚注而回退，随后在本机唯一定位并还原原文；没有追加模型调用。
候选命中、引用核验与语义质量继续分开计分，详见复核文档。
