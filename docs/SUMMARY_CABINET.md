# 独立摘要柜：两阶段合成原型

2026-11-10。工作线 `codex/offline-summary-cabinet-2026-11-10`，接续 `ad0dd3e`。

目标是“先写好摘要入独立柜，再按问题递短卡，必要时展开原文”。当前实现只接受
固定合成资料，不读取真实数据库，不接入 MCP、Bot、导入任务或生产服务。
它验证流程，不代表模型的语义准确性已经达标。

## 两种职责可以由不同模型承担

| 职责 | 做什么 | 当前状态 |
|---|---|---|
| 入库侧摘要生成者 | 读一小段原文，写事实、状态、日期及引文编号 | 注入接口已实现；Venice 仅作合成试验 |
| 查询侧问句理解者 | 将自然问句拆成受约束的检索条件 | M22 待做；可独立评估 OpenAI 等供应商 |
| 本地证据层 | 筛来源、检查复核与版本、控制篇幅、展开原文 | 合成原型已实现，不调用模型 |

换问句模型不会要求旧摘要重写。摘要记录自己的供应商、模型、提示/校验版本与
来源指纹，查询者按这些来源信息读取。实际 CLI 目前只有字面词项匹配，不能把
`--query` 的存在误认为已经能理解自然语言或解决日期召回问题。

## 怎样保存和读取

- `summary_cabinet.plan` 按身份、来源、房间切窗口，最多 6 条、8000 字，重叠 1 条；
  原型最多 12 个房间、每房 120 条、总计 120 个窗口。不会静默截断过大的输入。
- 每次生成前先保存 `started`，再由付费入口写消费预留；返回后保存 `draft`、`rejected`
  或 `failed`。中断留下 `started`。重复执行不自动重试这些任务，也不重扣已完成任务。
- 本地 `summaries.sqlite3` 只放派生原稿、状态与复核历史。合成源另存
  `synthetic-source.json`；运行清单和提示/结构版本单独保存。
- 摘要必须通过证据校验且 `status=ok`，再经过独立语义复核才能参与查询。
  复核绑定完整摘要哈希；后改输出不能继承旧批准。撤回追加历史，不删除原稿。
- 默认短包最多 3 张卡、3200 字符（含完整 JSON 结构），不重复附整段引文。
  展开时再次检查身份、来源、内容指纹与复核，返回被引用的当前原记录。
- 没有可用摘要时退回当前合成原文的字面匹配，最多 3 条、每条前 240 字，明确截断；
  没命中不能代表事情未发生。查询与展开使用 SQLite 只读连接，均无模型调用。
- 房间内容改变时整房旧卡失效并保留。此策略保守，不是已优化的增量重算方案。
  更换写摘要的供应商、模型或提示/校验版本同样产生新身份，不覆盖旧版本。

这里的 `scope_id` 与来源列表由试验调用方提供，尚未与生产认证/撤权连接；它不是
可以直接公开暴露的服务接口。自动摘要缓存也不是 M25 人工维护的长期提炼记忆。

## 离线试跑

```powershell
python scripts/summary_cabinet_trial.py
python scripts/summary_cabinet_trial.py --exercise-fixture --output-dir <新的本地试验目录>
python scripts/summary_cabinet_trial.py --exercise-fixture --output-dir <同一目录> --resume
python scripts/summary_cabinet_trial.py --output-dir <同一目录> --query 橘灯
python scripts/summary_cabinet_trial.py --output-dir <同一目录> --expand-job <查询返回的job_id>
```

默认只显示计划。`--exercise-fixture` 使用明示的参考答案，生成者标为
`reference-fixture-not-a-model`；不能拿它的正确率当真实模型成绩。
固定四房覆盖已完成事件、偏好、取消计划、关系方向纠正；不同来源故意复用记录 ID。

## 有预算的真实模型试验

```powershell
python scripts/summary_cabinet_trial.py --allow-live-api `
  --writer-model mistral-small-3-2-24b-instruct `
  --output-dir <新的私有试验目录> `
  --key-file <已有DPAPI凭据文件> --budget-ledger <已有累计账本>
```

只发送上述固定合成源，不发送参考答案或复核目标。沿用现有授权、价格核验、私有模型
校验与累计账本；最多四次生成，整批先核费用上限。消费失败也不自动退回预留或重试。
失败原稿和首份报告保留，显式 `--resume` 只补尚未尝试的任务，另存续跑报告。
额度不足、授权失败或网络错误时停止，不更换供应商或跳过 TLS 校验。

模型稿不会自动复核通过。`Cabinet.review` 必须由独立复核步骤显式调用并写明复核者、
结论和原因；结构验证和模型自己声称“通过”都不算批准。本轮使用者仍需复查事实，
不能把合成稿审核当作真实记忆的批量放行机制。

## 下一道门

1. 语义质量：完成/计划/取消、纠正方向、后来复述与事件日期分开验，保留失败原卷。
2. 跨窗口审计：后文纠正或取消不能留下旧卡继续当当前事实，重叠窗口需要去冗余。
3. 查询模型：另选模型、另定预算；先只发问题，不能自动向新供应商发送私人摘要或原文。
4. 真实数据：另定最小片段、隐私与授权方案；先影子比对，再考虑真实导入和正式入口。

回退只需停用这个独立试验入口；原始数据库、现有召回与失败档案均保留。
