## 固定材料与比较方式

|---|---:|---|

共 27 条记录、2,421 字；九道合成题占 2,324 字。两家各一次十二题批次。
同一提示、原文、证据编号及响应结构；评分目标、禁错项、分组标签不进入模型输入。
新题不是独立盲题：出题、提示制定和语义复核仍由同一助手完成，成绩必须按三组分开报告。
不能把已调整过的旧题或这次开发题称为真实留出卷。

长题含日常细节和跨消息更正；不在原文中插入标准答案或要求模型执行评分指令。
来源保持逐字片段，包含每条原记录编号与位置。私有片段仅有局部编号、原消息时间未知，
不冒充从 Echo 独立核验过的完整事件。

## 第二轮共同约定

- 同一计划只保留最终状态。取消以后不再另列仍有效的计划；被推翻的断言放历史字段。
- 原因问句属于猜测。回答问题可标为直接澄清，不能为了填纠正字段伪造曾经确认的旧断言。
- 日期、对象与更改依据分散时一起引用。已完成准备和尚未发生/取消的活动分别判断。
- 省略对象和代词指向不清时保留歧义，不自行补生理原因、对象身份或材料没写的细节。
- 长题可列至多八条事实，给工程、生活、感受留出空间；首轮六条上限和首轮答卷保留不改。

首次离线草案沿用六条事实容量，检查后发现不足以同时容纳长题的独立事实，已在调用前
另存八条容量的冻结版；原文字数、发送目的地和费用上界均未改变。
两家格式接法仍有差异：OpenAI 用 Responses 严格结构，DeepSeek 用 JSON object；
这些是实验条件，不据此声称完全相同的推理计算量。

## 验收与减重

先核对语义：人物方向、当前/历史、日期关系、否定、感受、未知边界与完整出处。
格式正确或引用编号有效，只证明机械约束，不能代替语义忠实。
显式拒答、空白、截断、漏题、字段错误和事实错误分别记录；任一组缺测不算整体合格。

对三道长题同时记录：

1. 原文字符数，以及事实正文＋历史正文＋未知项的总字符数；目标比例不超过 60%。
2. 包含字段与引用编号的完整结构字节数，以及原始正文的 UTF-8 字节数。
3. 保真审阅结果。即使比例很低，遗漏关键事实、拒答或空白也不能成为成功的减重。

这些字符与字节指标不是 token 账单，也不是最终 MCP 交付包的大小。
本轮尚不验证检索增益，不将三段六百余字的结果外推到整房长文或二十多万条记录。

### 保真与状态方面的发现

- GPT 的原因疑问已正确按澄清处理，不再出现首轮缺纠正历史字段的问题。取消计划和原定
  日期关系保留，长篇日常、工程及情感的主要内容也能分开整理。偏好开始时间未知等边界
  仍有未显式整理之处，不能把结构过关写成所有要求都已满足。
- GPT 的亲密长题正确更正事件日期，却在两条感受上填写 `event_date`，与
  `not_applicable` 状态冲突；其中一条引用也没带回载日期的前文。这是真实字段/出处错误，
  不是首轮中文日期检查器误判。该题原失败保留。
- DeepSeek 的两道取消旧题去掉了独立旧计划并补齐日期依据，是实际改善。但茶名纠正后，
  被推翻的旧说法仍另作普通事实；多处对方姓名来自前句，当前事实只引后句。
- DeepSeek 的日常长题把已完成买票和未来出行日期挤在同一条 `happened` 事实中；
  亲密长题又把旧日期另列普通事实且填错状态组合。多件事塞同一条，文字大致正确也会让
  后续按字段检索与局部展开出错。
- 两家都回应了这批三段私人片段，保留其亲密性质和不确定表达。GPT 仍有把省略对象说得
  比孤立片段更具体的情况，保守待复核；DeepSeek 更偏整句复述。该结论仅适用于本批材料。
- 片段中的动作叙述还暴露一个契约口径：GPT 多按“原话叙述已发生”标 `happened`，
  DeepSeek 有时按“未独立现实核验”标 `unknown`。应把**叙述中的事件状态**与**来源是否
  独立核验**分开，而不是直接把其中一家判成事实错误，或把所有聊天回忆都抹成未知。

### 正文缩短了，结构开销仍需处理

| 长题 | 原文字符 | GPT 正文＋历史＋未知项 | DeepSeek 正文＋历史＋未知项 |
|---|---:|---:|---:|
| 日常与工程 | 633 | 235（37.1%） | 413（65.2%） |
| 情感表达 | 637 | 270（42.4%） | 310（48.7%） |
| 非露骨亲密回忆 | 646 | 240（37.2%） | 381（59.0%） |

这里也列出尚未通过结构/语义检查的答卷尺寸，**只作诊断，不能算合格压缩**。
DeepSeek 日常长题未达到 60% 的正文目标。

首份程序报告的 `structured_bytes` 使用带缩进的归档 JSON，额外尺寸审计另算去空白的
紧凑 JSON，避免把归档排版开销冒充必然的传输负担。紧凑结构仍占原始正文 UTF-8 字节的：
GPT 约 **88.6% / 100.7% / 82.3%**，DeepSeek 约 **124.5% / 90.9% / 110.5%**。
这些结构还没有包含最终 MCP 的来源展开指针封装；也不是 token 比例。
因此不能只凭正文变短，就断言交付给主助手的整包已经显著减重。
