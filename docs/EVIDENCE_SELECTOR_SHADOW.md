## 修的具体问题

M22 的问句模型能追加查询，但短包仍靠词面排序：提到主题的旁话可能挤掉答案，
长称呼和短称呼不一致又可能把有用记录全部挡掉。新层在这些候选之后，单独判断
“这段原文能不能回答当前问题”，不将主题匹配当成语义判断，也不补写答案。

```text
原问句 → 原有只读召回 + 至多两次补查（M22）
       → 各轮交替取有限候选 → 模型判断关系与引用原话
       → 本地检查编号、逐字引用、冲突与篇幅
       → 短证据包 / 明确不足 / 保留旧短包回退
```

这是查询侧的一个部件，不代替导入侧独立摘要柜。底层没找到的记录仍不在候选里，
筛选模型不能恢复一个从未看过的答案，也不能将有限候选宣称为完整历史。

## 契约和边界

- `refine_shadow` 为显式注入接口，无默认网络调用。原始 `original / passes / brief`
  保留不动，新增输出的 `brief` 才供助手消费；`prepared / judgments` 仅供本机审计。
- 最多三轮、每轮十条的输入中，按轮次交替取最多十二条；相同来源、房间及编号的
  重复记录只取一次，同一身份的内容、角色或截断状态变化即回退。候选未用词面主题
  过滤，给语义判断保留识别短称呼的机会；未纳入数量明确记录。
- 模型收到临时编号、来源类型、说话角色、每条最多 400 字符的连续摘录及截断标记。
  问句与候选数据合计最多 24,000 UTF-8 bytes；完整 HTTP 请求还包括另行计费的提示和 schema。
  原始编号、房间号、日期、指纹、标准答案及大段调试信息不发送。
- 输出只有 `judgments / sufficiency / gap`，每个候选必须恰好判断一次。关系分为
  `answers / context / irrelevant / uncertain`。无关和旁话不凑条数；对象不明和
  冲突必须保留不确定性，不能先信第一条。现有确定性冲突组不许只留一边。
- `answers / uncertain` 给出最长 300 字符的定位提示。本地优先要求原样唯一匹配；
  v3 仅对成对 `**` 排版标记提供可逆定位，从源文恢复包括标记的唯一连续切片。
  不放宽字句、数字、空白、标点、代码或转义差异，重叠重复也视为歧义；恢复后的
  原文仍最多 300 字符，并标注 `quote_resolution`。偏移、来源与说话角色由本地恢复。
  这验证引用出处与机械一致性，**不证明模型的语义判断正确**。
- 相同完整观察文本、角色、记录时间、冲突组、关系和引用可压成一次展示，保留全部
  来源指针；不认定为同一事件、镜像或独立佐证。截断文本不据此合并。
- 整个最终 JSON 最多 12,000 bytes，最多六项引用；未纳入的候选、被容量挤出的入选
  项以及缺少覆盖结论均要求继续取证。未知覆盖仍为 `null`，不能转成“没有缺口”。
- 日期、来源、否定、角色、最早/最近等既有受限问句不进入这个影子筛选器；没有放宽
  M22 的保守限制。模型超时、非法输出或验证失败不重试，回到原有短包。
- 指纹字段名为 `observed_content_sha256`：被 gateway 截断的观察片段不是完整原文，
  不得把该哈希盲当作 `expand_record` 的完整原文指纹。所有引用仍有精确记录编号。

## 模型接法与费用

继续使用既有 DPAPI 凭据和受限 HTTP 传输，无新依赖、无工具调用、无网页搜索，
不保留推理项。GPT 使用 `gpt-5.6-sol` 的 Responses strict JSON / low reasoning，
Mistral 使用 `mistral-small-3-2-24b-instruct` 的 JSON schema；两者 `store=false`、
最多 1,800 输出 token。关闭响应存储不代表已经签订零保留协议。

依据：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)、
[GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)、
[Venice Chat Completions](https://docs.venice.ai/api-reference/endpoint/chat/completions)。
各模型仍执行既有价格、可用性及 Venice 私有模型检查，不自行切换型号。

累计账本不重置、不自动退还保守预留。OpenAI 原上限 0.50 美元，经本轮明确批准调至
1.00 美元；随后 Liora 明确委托小额、可控的试验额度调整，本轮保留备份与审计后设为
2.00 美元。只有新筛选试验入口可读取这份较高上限；旧试验调用方的较低上限继续拒绝
更高账本，不能借新接口悄悄扩大旧任务。平台钥匙权限未修改。

Venice 仍沿用原 0.10 美元累计上限。未成功的调用和被拒收结果也保留预留与回执。
请求与实现先冻结，先持久化开始标记和费用再调用；恢复仅复用既有结果，中断不重试。
