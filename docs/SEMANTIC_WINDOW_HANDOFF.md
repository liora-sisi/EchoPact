## 修复的具体缺口

上一步能定位一条长记录的后半段，但现有网关正文只返回有限前缀。
如果只把父记录编号交给旧摘录器，真正命中的尾句仍可能没有进入模型输入。

`backend/memory/semantic_evidence.py` 复用固定身份 `expand_record`，依据
原文 SHA-256 和 Unicode 字符偏移，逐段回取匹配窗口。原始记录不截改，
也不把中间一段伪装成从零开始的完整正文。

- 首个窗口优先语义命中；另保留已有词面摘录位置及第二个语义位置，单记录至多三窗。
  先给每个排名记录一窗，再分配额外窗口；只有被已有窗口完整包含的片段才去掉。
- 同一个记录编号可以有不同偏移的卡片，不因编号相同丢掉后面的更正。
- 可带冻结的 planner 原词复用既有词面摘录器。本轮新虚构试卷没有调用 planner，
  词面臂使用现有无主题词时的开头窗口；不能把它当完整旧小管家链路的性能代表。
- 两臂都遵守同一上限：至多十条排名记录、十二张卡、每卡四百字符、
  模型请求二万四千 UTF-8 字节、最终短包一万二千字节。
  **上限相同不等于实际卡数或实际字节相同**；报告保留两臂实际占用。
- 原库代际、当前权限、来源元数据、原文指纹和具体文字在装卡及模型返回后复核。
  查询中撤权或源库变化直接拒绝旧包，不能退回撤权前的缓存。
- 模型只收到临时卡号、原文、来源类型、发言角色和片段是否完整；真实编号、
  原文指纹、语义分数与完整审计留在本机。模型输入字段严格白名单。
- 没有模型或模型失败时，只能返回标有 `not_assessed` 的原文预览，不能伪装成已选答案。
  模型成功后的引文仍逐字核验；引用表压缩后可无损展开，整包再次检查上限。

`observed_content_sha256` 来自受权限保护的完整原文指纹，不是截出的四百字的哈希。
因此 `source_truncated=false` 表示引用绑定完整原文；模型卡上的 `excerpt_incomplete`
另外说明它实际只看到一个窗口。不能把这两个标记混为一谈。
