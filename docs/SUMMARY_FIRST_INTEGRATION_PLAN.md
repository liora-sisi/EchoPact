# 先做可直接使用的摘要与语义检索

2026-11-25。Liora 提出：摘要写好后，查询材料与筛选方式还会变化；不应继续把额外查询
小管家的全面验收当成摘要施工的前置条件。本计划据当前代码明确顺序，未启用任何新生产入口。

## 当前看到的三种短内容

| 内容 | 实际来源 | 当前状态 |
|---|---|---|
| MCP `detail=brief` 目录 | 每条原文从开头截最多 120 个字符；整包紧张时可缩至 60 或 0，并保留编号及省略提示 | 正式接口已有 |
| 查询小管家短包 | 从命中的原文窗口中选逐字引文，补有限邻文，保留出处及缺口 | 隔离试验已有；不是预写摘要 |
| 入库侧摘要 | 模型阅读有界原文后提炼事实、状态、日期、纠正及引用，另存、复核 | 独立合成原型；未批量生成真实摘要、未接正式查询 |

正式预览在 `backend/mcp/recall_packets.py::_brief_memory` 中截取 `content[:120]`，
不是问题相关窗口，也不是模型摘要。底层全文索引仍使用原始 `content`，不是只搜这 120 字。
后段匹配可能找到了记录，却没有出现在开头预览中；助手若没展开，就会漏读或误判相关性。
原始正文没有因此删除，`expand_record` 能按编号与指纹分段精确回取。
候选根本没被检索到是另一类遗漏，改变展示不能自动解决。

摘要有助于让开头看不出的主题更容易辨认，但也可能漏掉细节、反转主体或保留旧结论。
不能因文字流畅就视作完整证据；原文检索与展开必须继续存在。

## 目标与分工

第一版优先让 Elion / 主助手直接使用：

```text
原始记录（完整保留）
  ├─ 原文关键词与向量索引 ──────────┐
  └─ 有界摘要生成 → 独立复核摘要柜 ──┤
                                    ▼
                    按权限合流、标明派生来源与缺口
                                    ▼
                    主助手读短卡，按需展开原文与邻文
```

自然问题的理解、选读和最终表达可由主助手承担，额外查询模型不是这条路线的必需依赖。
第三岗位保留为可开关的增强：若在同样资料与预算下确实减少追查、降低上下文负担，
且没有增加遗漏或错误，再接入。不能因已经投入施工而默认它必然优于直接使用。

原文向量继续定位原文；摘要是独立的辅助检索与展示层，不替换原始语义索引。
本计划未决定给摘要另建向量、选择新的供应商或扩大外发；这些若有必要应单列比较。

## 调整后的顺序

1. **保留已测查询基线。** `bc4bf58a6c4a9969de8e33e7ce358fc5180413e0` 保存当前向量接头、
   初选、纠正复核、预算与短包试验。暂不扩展第三岗位的新提示轮次或把其正式接入列为下一步。
   普通缺陷修复和不影响生产的证据校验仍可进行，已有失败及试卷不删除。
2. **先做好小批摘要样板。** 从既有合成材料开始，明确完成/计划/取消、角色方向、后文纠正、
   未知日期、跨窗口缺口的验收；保存首份生成稿和失败。模型产生的稿不能自行批准为合格。
   先修摘要质量与复核、失效机制，不立即跑全库。真实小样须另有明确的数据范围。
   按[摘要约定与验收](SUMMARY_CONTRACT.md)分开门牌、关键事实、原话出处，分别核验生活与工程材料；
   先冻结内容要求和判卷，再比较模型，不能只以语言流畅放行。
3. **接主助手直接可用的小规模闭环。** 把合格摘要及其原文指向接入检索和展开，保留原文
   关键词/向量路线。先解决来源身份、版本、重复占位和摘要漏项补查，再考虑扩大范围。
4. **验这条完整使用路线。** 比较原文检索与摘要辅助检索的证据覆盖、最终理解、追查次数、
   上下文字节、延迟及费用。接收方不带开发答案，正式成绩按[独立留出卷协议](CARETAKER_HOLDOUT_PROTOCOL.md)
   留首卷；旧题用于回归，不反复冒充盲题。全量索引、资源与回退合格后才部署。
5. **再衡量第三岗位的增益。** 在相同检索语料、摘要版本、权限和材料预算下，对比主助手
   直接使用与查询小管家辅助使用。收益不足就继续保留直用路线，不为第三岗位强行增加链路。

步骤 3 的“摘要＋原文检索＋展开”先独立闭环；不等步骤 5 才允许它接受正式验收。
这替代此前“先完成第三岗位读包/接入，再集中补摘要作者”的下一阶段排序，
没有降低任何一条实际部署路线的证据与资源要求。

## 先验保真，再验真实长资料的收益

2026-11-25，Liora 进一步明确：六百余字的简单合成题不能代表长期生活档案。
先检查准确、关键内容不遗漏、不编造，再用有明确范围的真实长对话验证空间收益。
按下面的层次推进，不把小样的压缩比例外推成整库效果：

1. **合成题守住已知底线。** 先列清必须保留的事实、称呼和感受，允许省去的重复，
   以及不得生成的结论；检查主体、日期、计划/完成/取消、否定、更正和精确出处。
   长合成题补跨段纠正、尾部线索与干扰事件，不能只把同一句重复填长。
   “不遗漏”指事先明确的关键信息完整；原话及未入摘要的细节继续保存在原库。
2. **真实长资料同时验质量和大小。** 在基础检查通过后，固定少量连续对话窗口，
   包括围绕少数事件反复讨论的材料，以及多件重要生活/工程事件交织的材料。
   保留先后、转述和更正语境，提前标注必保信息，再生成摘要；不只抽答案附近几句。
   分段整理时记录边界与跨段依赖，不把整房或二十多万条一次送进模型。
   真实题仍检查捏造、漏项、主体和时间，不能因为合成题通过就只测尺寸。
3. **再验按问题取用的实际开销。** 固定同一批资料与问题，比较原文路线和摘要辅助路线：
   是否答对、必要证据是否齐、首包大小、原话展开次数与累计交付量、费用及耗时。
   原文、摘要柜、后台核验档案的磁盘占用另报；上下文减重不意味着总存储必然变小。
   小批真实开发题不能冒充已通过全库规模测试或独立盲卷。

真实开发材料揭出的错误保留首卷并进入回归；摘要作者和读包结构仍可据此改进。
正式留出卷继续隔离，不把已经参与调整的真实窗口重复包装成盲测。
选择实际窗口时固定来源、边界和费用，沿用有效授权；本次计划更新不执行新增模型调用。

## 现在就固定的接头要求

- 摘要、逐字引文和目录预览必须明确区分，摘要不得被引用成原话。
- 摘要关联当前可见的来源、房间、原始记录、指纹与生成/复核版本；生产权限和撤权需真正接通，
  不能直接信任合成原型中调用方提供的 `scope_id`。
- 摘要命中与原文命中按来源身份和原文引用汇合；同一片段不因两路命中占两份名额。
  同记录的不同必要窗口、不同分支的矛盾和纠正仍保留，不能按意思相近吞并。
- 摘要缺失、未复核、失效或覆盖不足时，原文路线仍可用；摘要没提到不能证明原文不存在。
  后文纠正与取消要能让过期摘要失效，不能只检查摘要对应的早期窗口是否改变。
- 模型作者、额外查询小管家和主助手分别验收；任一方的过关不替另一方背书。
  现有逐字回查、边界检查和可展开出处可继续复用，摘要接入后的新组合必须重新比较。
