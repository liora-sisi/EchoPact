# 按事件取读：减少无关卡片内容，保留纠正与原文展开

2026-11-28，接续[摘要日期与状态校对](SUMMARY_STATE_REVIEW.md)。新增 `read_events`：
助手从目录指定事件编号后，读取完整的该事件及必要的纠正、后续更新和冲突，
不再因为它与别的事件恰好装在同一张物理卡片里，就把旁边的话题也整张搬回来。

四份既有合成候选稿的离线对照中，单独选择一个事件的阅读包有所缩小。
例如密集题选择“围巾”时，旧读法带回五件事，新读法只带回围巾事件；
阅读包从 4,113 B 到 1,250 B。把目录也计算在内，则从 6,516 B 到 3,653 B。
**这是取读方式的改进，没有重新生成摘要，也没有证明自然问题一定能选对事件。**
正式 MCP、Bot 和真实摘要柜未切换。

## 行为约定

入口为 `backend/memory/summary_event_booklet.py::read_events`。
调用继续携带已验证的审计、书册、当前合成来源及固定身份，新增参数为 `event_ids`。
已有 `catalogue` 已返回这些事件编号，`expand` 的事实、未知和关系编号保持不变。

- 完整保留所选事件的标题、类型、每项文字、状态、时间角色、旧说法、感受及未知项。
  使用与旧卡片相同的呈现函数，不做同义合并、截句或再次摘要。
- `corrects`、`updates`、`conflicts` 双向并递归带齐必要事件；普通 `related` 保留关系指针，
  但不强制展开另一件事。历史计划在本事件内的后续更新也仍完整保留。
- 来源信息只在整包中放一次，关系只列一次；全局未知和作者声明的缺口照常保留。
  输出仍标为待复核，作者状态和结构问题不能因读取成功而变成验收通过。
- 同身份、来源指纹、审计和书册都必须匹配。所选事件或必要关联已因卡片预算受阻时，整组暂扣。
  最终交付预算按完整 JSON 的 UTF-8 字节计算，包含元数据和必要上下文；超限不截掉内容。
- 未选事件仍保留在目录中。当前读取没有某件事，不证明源档案没有发生过。
  调用方还需要判断选读范围、是否缺证以及应否继续展开。

原来的 `read_cards` 和书册格式没有更改，旧答卷、旧卡片指纹及原始资料保持原样。
本入口仍沿用合成资料约束，尚未接生产身份与真实摘要索引。

## 同材料离线对照

使用日期状态校对 V3 已保存的四份答卷，不再调用模型。
先核对冻结请求、首稿及派生审计，再对每个事件分别执行一次旧卡片取读和新事件取读；
另做一次“读取全部事件”对照。共 20 个单事件探针及 4 个全量探针。

这些编号是预先明确指定的，**不是自然语言检索准确率考试**。
包内所有保留事件逐项对照旧卡片，文字不变；127 项事实、未知及关系继续精确回查到原文。
来源和排版通过不替代语义质量验收，也不会补回作者原本漏掉的内容。

| 材料 | 单事件探针数 | 阅读包减少范围 | 读取全部：旧 / 新 | 原文正文 |
|---|---:|---:|---:|---:|
| 日常混合 | 2 | 34.47%–42.93% | 3,580 / 3,520 B | 1,857 B |
| 少事件长讨论 | 4 | 40.68%–76.71% | 6,003 / 5,471 B | 6,417 B |
| 多事件交织 | 13 | 46.38%–73.50% | 10,577 / 9,663 B | 7,335 B |
| 手写正确对照 | 1 | 4.29% | 1,633 / 1,563 B | 837 B |

旧、新数值都包含各自完整交付封装。上表与以前只把卡片相加的 10,167 B 等数值口径不同，
不能直接混用。目录尚未计入上表百分比；报告另列了“目录＋读取”的完整字节数。

密集题的三个具体例子：

| 明确选择的事件 | 旧 / 新阅读包 | 含目录：旧 / 新 |
|---|---:|---:|
| 围巾来历与收到时间 | 4,113 / 1,250 B | 6,516 / 3,653 B |
| 展览取消与遗憾 | 4,305 / 1,141 B | 6,708 / 3,544 B |
| 散步日期更正及相邻晚饭 | 4,305 / 1,603 B | 6,708 / 4,006 B |

全量读取的密集稿仍比原文正文大，本轮没有解决摘要文字和结构的全部重复。
真正的单次回答还可能读取多个事件、展开原文或返回目录重选，因此也不能把本表当成最终问答节省比例。
