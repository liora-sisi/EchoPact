# 时间角色与历史安排：结构已接好，作者仍未通过

2026-11-28，接续[日期原句索引复验](SUMMARY_DATE_GROUNDING.md)。V5 将行动发生日、
原定活动日、取消决定日分开，并将已被后文改变的计划明确标为历史安排。
展开历史安排时，会一并带回后续改期或取消的原句；这些原句超出预算时整包暂扣，不能只留下旧计划。

三道固定合成长题实考后，部分时间与历史状态改善，但模型仍会选错日期角色，
也会把“没有确认到账”标成“明确没有到账”。**本轮完成的是试验结构与复核，摘要作者仍未获准上岗。**
V5 是内部作者约定版本，不是正式 Echo 产品版本。正式 MCP、Bot、原始数据库和额外查询小管家均未切换。

## 改了什么

模型继续从宿主提取的日期出现位置中选择编号；宿主保存原句、偏移、记录和指纹。
同一天出现在不同地方仍是不同编号，不允许借另一件事或消息时间补年份。

- `happened` 选择 `occurred_at_ref`，限定本项行动发生日。
- `planned` 选择 `planned_for_ref`；`plan_scope` 区分仍有效的安排和已被后文改变的历史安排。
  历史安排的 `replaced_by` 指向同一事件里更新它的事实，可连到改期、取消或完成。
- `cancelled` 分别选择 `cancelled_at_ref` 和 `planned_for_ref`，缺哪一个就留空。
  两者相同也必须有各自的语义依据，字段存在不能替代这一步。
- 旧计划不会被删去；卡片显示“历史安排”及后续编号。展开时跟随更新链，把后续原文一起返回。
  无效、自指和循环更新会诊断；结构有效仍不证明更新指向的确是同一件事。

模型首稿不改写，派生阅读稿保留 `time_context`，日期角色另外进入后台核验档案。
新约定仅由明确选择 V5 启用；默认作者仍是 V2。V2/V3/V4 冻结作业指纹保持不变，旧报告不重写。

三稿基础结构检查均无错误，日期索引诊断分别为 0 / 0 / 1。
118 项事实、未知与关系可精确展开；另外复查全部 5 个历史安排，确认更新链与后续原文一同展开。
所有内容能排进卡片，无未引用记录。这些是来源和排版检查，**不是 118 项语义正确，也不证明摘要无遗漏**。

密集题还有“围巾已在春天收到，但具体日期未知”被标成“是否发生未知”的问题。
它和退款问题共同说明：需要区分“事件是否发生”和“我们是否知道它的日期或结果”，
不能只看一句里出现了“没”“不知道”便选状态。

这份密集稿保留了末尾称呼、双方爱意、平时表达的期待、被听见的感受、仍疲惫和未执行的备份计划；
稀疏稿保留了外号、陪伴需求、取消失落、相互期待和未发布状态。
这些局部保留不能抵消日期和状态错误，也不能外推成对任意真实长对话的保证。
