# 对象复核：并存缺口与补证顺序

2026-11-22。对象复核当前为 `echo-object-evidence-review-v8`，通用筛选器仍为 v5。
承接[同材料换问法诊断](CARETAKER_IDENTITY_PHRASING.md)。仍为隔离试验，未接入正式 MCP、Bot 或导入侧摘要。

## 从单个原因改为多个独立缺口

旧接口只有 `gap`，无法同时表达“还不确定问哪两个对象”和“同一对象有未解决的矛盾”。
v7 在对象复核响应中新增必填 `gaps`，v8 继续修正无明确指代时从并列描述猜对象的问题。
原 `gap` 保留为第一项，表示补证顺序；不是对原文真实性的裁决。

固定顺序为 `object_identity → conflicting_evidence → excerpt_incomplete → missing_answer`。
只列有依据的缺口，不重复；没有缺口时 `gaps=[] / gap=none`。对象不明或冲突仍须报告 `ambiguous`。
多个对象属性不同不等于同一对象事实冲突；已明确解释并替代的旧稿，也不自动成为未解决冲突。

本机校验拒绝乱序、重复、未知原因、主原因不一致，以及没有任何截断候选却声称摘录截断的响应。
已知冲突组可将冲突作为第二原因，但两方仍必须保留为 `uncertain`，不能删去其中一方。
短包附固定的补证建议步骤；这些只是建议，**没有自动追加检索或调用模型**。

通用筛选器仍要求旧三字段格式。历史对象答卷只能通过显式 `legacy_single_gap=True` 重放，
标为旧单原因答卷，不补造第二原因；实际对象复核缺少新字段时回退原短包，不自动兼容放行。
引用、原文顺序、关联组完整性、12,000 字节上限和原库只读边界保持。

v7 实际四次调用，严格 **3/4**：在并存题中默认采用重复出现的一对，将第三个可能对象丢为背景。
v8 只补通用指代规则：两件曾在同一句或多次比较中并列，不足以排除其他对象；需要可核验的明确关联。
同四题、同来源、同顺序、同 schema、同预期，仅系统指令改变，实际再调用四次，严格 **4/4**。
第一次失败没有改判或覆盖。这是开发诊断与已见题复考，不是独立留出集，也不能证明稳定准确率。
