## 修复及复验，分别记账

### 相同可见邻文共享名额，原分支保持独立

`semantic_ordered_evidence` v2 将“最多四个分支成员关系”改成“最多四组不同的可见
有序记录窗口”。每个根记录最多检查六十四条成员关系，仍只读同源、同房、同分支前后两条。
仅当整个有序记录编号列表完全一致时共享展示窗口；不同结论、位置歧义和超限继续延后。
这不是合并原始分支，也不能证明窗口以外各分支相同。最多十二卡等模型材料上限未扩大。

对象旧题复用原初选答卷、**零 API 调用**：三十条成员关系中去掉二十八份重复展示，
两组根记录共八张卡可以完整准备，未再触发容量退回。但关键纠正在另一个被延后的候选里，
不属于这两组邻文；本次修复没有把它自动捞回，也没有进行新的语义复核。

### 不把“不知道答案”当作禁止按原问查找

问句提示 v4 明确区分可检索主题和未知答案。单独增加一次规划实测后，新问法仍返回
`needs_clue`。此时实际输入仍是问号；**该校准无效，不能判定提示修订或正常问句规划失败**。
原响应保存不改写。

`semantic_caretaker_pipeline` v2 允许契约有效的 `needs_clue` / `no_rewrite` 继续做一次
原问混合检索，不臆造追加词，也不触发对象补查；`needs_clue` 必须在最终包保留并强制
`needs_more_evidence=true`。日期/来源等确定性限制、禁用规划、非法输出、供应商失败
依旧回到原路线。调用数和材料上限不变。

新问法随后复用已保存的同一份负面规划答卷，只新增初选、复核**两次**调用。
原问检索已执行，但目标不在词面或向量前十，也不在初选目录；复核最终保留零条答案，
明确缺证。最终包 **1,829 字节**，比旧目录更大，目标仍未找到，不能算质量改善。

额外本机离线排名诊断当时记录为 **4/622 → 286/622**。后者实际是问号查询，
不能用于证明自然措辞敏感。原排名计算可复现、源库及索引未变，并不代表输入文字正确。
完整中文在不改切块、模型或合流参数的情况下复验为纯向量第 1、合流第 2。
