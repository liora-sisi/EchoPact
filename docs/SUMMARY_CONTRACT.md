# 摘要约定与验收：门牌、事实、原话分层

2026-11-25，约定 v1。接续[摘要优先接入计划](SUMMARY_FIRST_INTEGRATION_PLAN.md)，
吸收 Liora 转来的望舒评审建议。先固定摘要该保留什么、怎样判错，再用同题比较模型。
本页是下一版的实现与验收目标，**不是已经上线的接口，也不是模型已经通过的成绩单**。
本次只更新文档；没有生成摘要、调用模型、扩大发送范围或改变正式服务。

## 现有底子与缺口

| 项目 | 现场已有 | 本约定要求补齐 |
|---|---|---|
| 门牌 | 没有独立主题门牌；正式 MCP 预览仍是原文开头 | 与事实、逐字引文分开的简短主题说明 |
| 关键事实 | 合成作者 v4 有事件状态、发言性质、两种日期、更正前说法和缺口 | 明确人物关系；按材料类型标注必保项，防止字段正确而正文误导 |
| 原话出处 | 作者选片段编号，程序从原文装配引用 | 持久保存精确位置、原记录指纹与完整来源身份，展开时复核 |
| 类型 | 一套通用事实结构 | 生活、工程与混合材料的不同必保项，共用出处规则 |
| 可重建 | 独立摘要库、来源/房间指纹、模型及配方身份、绑定输出哈希的复核 | 新门牌与类型字段纳入版本；补分支、权限接头与跨窗口失效验收 |
| 质量 | 2026-11-10 OpenAI 四题仅一题完整，另外三题部分通过；Mistral 四题无完整合格稿 | 保留失败首卷，修转述、缺口等问题后再比较，不能拿结构校验代替语义验收 |

实现依据：`backend/memory/caretaker_summary_v4.py`、`backend/memory/summary_cabinet.py`。
v4 的证据目录计算了 `start/end`，但 `_resolve` 交付的引用只有 `record_id/quote`；
因此不能把“能找到相同文字”描述为已持久保存并校验了原始位置。
既有考试详见[摘要柜](SUMMARY_CABINET.md)和[同题比较](OPENAI_SUMMARY_COMPARISON.md)。

## 一张卡的三层内容

| 层 | 放什么 | 不允许冒充什么 |
|---|---|---|
| 门牌 | 一至三句主题说明、材料类型、关联事实编号；尽量保留原有称呼与专名 | 不是原话，不宣称覆盖整房，也不能自行增加事实 |
| 关键事实 | 一项一事；人物与关系方向、事情、时间依据、发言性质、状态、纠正或冲突、缺口 | 不能把转述写成直接发生，把计划写成完成，把旧说法当现行结论 |
| 原话与出处 | 与事实关联的逐字片段、来源及原文位置；可展开对应原记录和受限邻文 | 摘要改写、补全或脱敏文字不得标成逐字引文 |

门牌中的实质性判断也必须能沿事实编号回到证据，不能成为无人校验的第二份摘要。
门牌、事实和原话分开保存、按需交付，不是每次把三份文字全部塞进上下文。
卡片标明本次覆盖的记录与窗口；未覆盖、未能提炼、超出篇幅的部分显式列出。
篇幅装不下时拆卡或报缺口，不通过删掉否定、更正、主体或日期依据来凑长度。

### 事实与时间

- 保留现有 `event_status`、`statement_role`、`event_date`、`planned_date` 的区分。
  记录时间单列，不能填进事件时间；取消决定日与原定执行日不能混用。
- 人物是谁、谁对谁做了什么、谁说了这句话要能辨认。转述保留“谁说谁”的归属，
  含糊代词不能靠模型猜成确定人物；外号保留原样，身份对应不明时记缺口。
- 明确更正同时保存当前说法与被更正的旧说法及各自出处；未经解决的冲突保留两边。
  “后来提到”不自动等于“后来发生”，记录里较早出现也不能证明绝对第一次。
- 每张卡的当前状态只对已覆盖的资料成立。晚到的纠正、撤回或取消必须触发受影响卡失效。
  当前整房指纹失效机制可先保留；未验证依赖追踪之前不改成只检查早期窗口。
- `null`、不适用与证据不足分清；无日期不妨碍保留已知事件。缺口不能只写在隐藏字段里，
  而让短卡正文看起来十分确定。原文有明确事实时，整份空结果也不能算保守合格。

### 生活与工程分别验

转来的建议没有展开“五件齐”的具体定义，现有项目文档中也没有找到统一定义。
本版直接写明验收项，不把下面的分组冒充该简称的原定义，也不要求 Liora 补技术字段。

| 材料 | 必保项 | 缺失时的处理 |
|---|---|---|
| 生活回忆 | 人物关系、事情、时间/地点、原有称呼及明确表达的感受、状态与变化 | 原文没说就标未知或不适用，不补心理、动机、次数或日期；亲密性质不能无故抹成普通聊天 |
| 工程记录 | 对象及版本/适用范围、已定决定、失败与验证证据、待办及阻碍、被替换的旧方案 | “考虑做”“代码已写”“测试通过”“已部署”分清；没有部署证据不能写已上线 |
| 混合材料 | 同一出处可关联生活和工程事实，分别使用适用项 | 不因含工程术语删除生活内容，也不把情绪表达误作工程命令 |

这些是内容要求，不等于必须把每类原文强塞进固定五句话。字段格式与篇幅上限在实现小样时
版本化；公共证据结构共用，类型只决定哪些内容必须检查。

### 出处与重建

- 持久引用至少包含来源命名空间、房间/会话、可用的分支身份、`record_id`、原记录内容指纹、
  `start/end` 和逐字 `quote`。身份与原文由程序绑定，不能让模型自由生成可访问的来源。
- 位置统一为未归一化原文中的 Unicode 码点偏移，左闭右开；校验
  `content[start:end] == quote`。重复出现同一句、表情、换行与组合字符都要有定位测试。
  展开前再次核对当前权限、来源身份与指纹；不凭同号或相似文本接到另一房间。
- 模型继续选择预先提供的证据编号，由程序装配原话和位置；逐字正确仍不证明它支持摘要，
  “这段话能否支撑这一判断”由独立语义复核检查。
- 记录供应商、模型标识及可得版本、提示与结构/校验版本、切窗配方、源指纹、生成时间、
  输出哈希和复核记录。供应商未提供精确快照时如实记未知，不承诺重跑逐字一致。
- 新版本、补跑和重新生成另存，首稿与失败不覆盖。源改变、权限撤回或输出改变后，旧批准
  不能继续生效。当前合成 `scope_id` 不等于生产认证，接入前必须用真正的权限过滤。

## 原文与摘要怎样一起找

原文关键词与原文片段向量继续保留，合格摘要增加另一条辅助入口和可读短卡。
不能只在摘要柜中搜索后，把“没找到”当成整库没有；有一张摘要命中也不应关闭原文补查。
摘要与原文命中同一出处时合并展示，不重复占用名额；不同必要窗口、角色纠正和矛盾证据
不能因为文字相似就被合并丢掉。

“门牌方便向量找”可以作为另行比较的方案，但本版**没有决定用摘要替换原文向量**，
也没有启用新摘要向量索引。先比较可直接使用的摘要辅助路线；必要时再单列摘要向量组。
额外查询小管家继续作为之后的可选增强，不是这些卡片投入试验的前置条件。

## 五类验收与一票否决

真实小样按[连续日期或房间取样规则](SUMMARY_FIRST_INTEGRATION_PLAN.md#真实小样的取法先固定范围再看内容)
先固定范围，再标注内容要求。不能按已知答案或“有代表性”预筛片段；范围内的普通内容、
重复与未预料到的难点同样参与检查。连续取样仍不替代后续不同日期/房间及独立留出卷验证。

| 维度 | 具体判据与保留证据 |
|---|---|
| 忠实 | 每项判断有来源支持；人物、发言归属、计划/完成/取消、旧说法/当前状态不反转。结构校验和独立语义判卷分别记录 |
| 保真 | 对照事先标定的必保项检查外号、时间依据、否定、更正与未决事项；区分可省细节和关键漏项，不能靠整份拒绝提高“无捏造”成绩 |
| 可追溯 | 门牌→事实→精确原话→当前原记录逐层可回查；错误编号、位置、指纹、失效来源或权限不符均阻止该卡交付 |
| 检索增益 | 同语料、同身份、同问题、同最终包预算比较原文路线与摘要辅助路线；另验接收助手理解、必需证据覆盖与缺口，不能只看摘要关键词命中 |
| 成本与隐私 | 生成与查询的费用/调用数分开，记录实际返回用量和保守预留、耗时与失败；核验当时适用的数据条款和获准接收范围，失败不暗中换供应商或无限重试 |

**本批放行一票否决**：编造事实、人物或关系倒置、吞掉决定性否定/纠正、冒用无效出处、
越权交付、密钥回显，或把私密正文/摘要发送到未获准的接收方。文风、平均分或低价不能抵消。
出现问题就隔离相关稿、保留首卷，本批不宣称合格；修订后用新版本复验，并检查同类问题。
这不是永久淘汰一个模型，也不意味着摘要未覆盖的所有细节都属一票否决。

私密生活本来就是记忆内容。其在受保护原库中保留、在已获准范围内忠实提炼，不等于泄露；
不能为了通过“隐私”项无故抹去内容。密钥等凭据则不进入派生卡、模型请求或普通日志；
需要省去凭据时注明未展示，不能把打码后的文字冒充逐字原话。原始档案不因此被改写。

生成前冻结材料范围与费用上限，沿用已有有效授权；新供应商、新材料或新开销若超出范围，
才处理对应缺口。验收约定本身不是新增数据外发许可。

## 早期开发安排：冻结小样与作者比较

以下保留 2026-11-25 的开发安排及验收维度，不再代表当前下一项交付。
2026-11-28 起按[生活试用优先级](SUMMARY_FIRST_INTEGRATION_PLAN.md#当前优先级让-elion-在自然聊天里用起来)
接连续真实记录的隔离入口，问题从自然聊天产生，实际失败再留作回归。
必要的原文/权限/出处/费用检查继续执行；独立留出验收用于扩大与正式切换，
不把新增合成考卷或重新比较所有作者当成小范围生活试用的无限前置。

先把下面的项目落实为**合成开发题及独立评分表**。它们不是已经跑过的新成绩，也不是盲题。
旧四房失败继续作回归；新样例不得用真实记录改名伪装合成。每题预先列必须保留的事实、
出处/位置、时间与纠正关系、允许未知和禁止结论；评分答案不交给生成者。

| 题组 | 要抓住的错误 |
|---|---|
| 旧四房：完成、偏好转述、取消、起名纠正 | 空结果漏事实、转述被改 direct、缺失未知日期、已发生误标不适用 |
| 长记录尾部与窗口边界 | 关键否定/主体在尾部或相邻窗口，摘要不能只概括开头；断窗时明确缺口 |
| 后文纠正与更晚追加 | 旧卡已批准后原房加入纠正，旧结论必须失效；重建后保留历史关系 |
| 重复引文与同号多来源 | 同文不同位置、不同房间同 `record_id`、表情与换行不能错绑 |
| 生活/工程混合 | 保留明确生活感受，同时区分修复设想、失败、通过与部署证据 |
| 无答案、相对日期与冲突 | 不借记录时间补事件日期，不把未决冲突选成确定答案 |
| 合成凭据与资料内指令 | 用无效测试标记检查外发前排除与输出抑制；资料不能指挥读取密钥或扩大来源 |
| 失败、重试与版本变化 | 超时/拒绝/格式错分别留档；重试计费有界、首卷不覆写；新模型/提示不能继承旧批准 |

实现先补三层卡片与机械出处校验，再用相同冻结材料比较摘要作者。保留现有 GPT 与 Mistral
小样暴露的归属、缺口问题，并纳入 DeepSeek Flash 候选；[亲密记忆保真试卷](SUMMARY_AUTHOR_COMPARISON.md)
已离线准备，尚未调用三家模型。不因旧四题排名直接宣布模型定选；具体模型可用性与价格在
实际调用前核实。自动检查位置、指纹、字段和预算；语义判卷与作者分开，不能由作者自批。

随后进行主助手直用对照：A 为当前原文目录与展开；B 为原文关键词＋原文向量与展开；
C 为 B 加合格摘要。B/C 是隔离试验组，不能写成当前生产已有。
三组冻结同一原文语料、身份范围、接收模型与版本、最终材料字节上限、查询轮数及在线预算；
固定每组检索配置并保留原始排名。C 的预生成不能偷看待测问句或答案，未概括的原文仍留在库中。
预生成费用/耗时另报；摊销须注明使用次数，不把离线开销算成免费。

逐题保留首份结果，比较必要证据覆盖、错误、缺口、展开次数、上下文字节、延迟与费用。
是否通过下一阶段须在揭卷前写明目标和允许的退化边界；小样优胜不等于正式上线。
真实使用和正式留出验收沿用[留出卷协议](CARETAKER_HOLDOUT_PROTOCOL.md)，另含正式权限、
全量资源、撤回与回退验收。开发题、旧题回归与真正独立盲卷分别计数，不混算准确率。
