# 摘要按事件分卡与关联回查

2026-11-25。本轮补齐本地合成原型的事件分组格式、分卡、跨卡关系和精确原话回查。
**只验证宿主能完整存放、交付已经写出的内容；未调用模型，不代表作者已能完整写出摘要。**
正式 Echo、真实资料、MCP、Telegram 和模型配置均未切换。

## 要解决什么

[单段对话对照](SUMMARY_SINGLE_WINDOW_COMPARISON.md)中，原/新提示都把密集长题写满
24 项，仍遗漏末尾的称呼、相互表达、感受和备份待办。本轮不再要求全窗挤进一张单表：

- 作者按事件组织事实、历史说法与未知；生活和工程事件可以共存。
- 宿主以完整事件为单位装卡；当前卡放不下，就另开卡，不裁掉后半段。
- 一个事件自身已经超过单卡预算时，明确列出被暂扣事件和所需字节，不悄悄拆断经过。
- 跨事件明确纠正、更新或未解决冲突，读取时必须一起带上。普通关联不自动展开。

事件分组、关系和必保内容仍须由作者提出、复核者检查；程序不会靠排版替作者补回漏写。
这也没有解决来源窗口之间的自动事件合并、增量重写或生产权限校验。

## 实际接头

实现位于 `backend/memory/summary_event_booklet.py`：

1. `prepare_author_window` 准备完整有界合成窗口，逐条保存来源顺序、时间和精确片段位置。
   每 240 个字符划一个引用片段，尾段也保留；所有片段一起交给作者，不单独截取消息开头。
   返回提示、来源目录和响应格式，没有答案标注，不调用 API。
2. `make_audit` 保留原始稿、完整来源、引用目录、模型与提示版本、来源指纹和未复核状态。
   事实沿用状态/日期/纠正约定；事件内未知、全局未知和跨事件关系也须有出处。
   拒绝不存在的引用、无效关系、自指及循环更新。可诊断的日期错误保留在原稿与报告中，
   不把它静默改成“正确稿”。
3. `build_booklet` 在完整 UTF-8 序列化字节预算内装卡。编号绑定原稿和排版预算，
   改动来源、作者、内容或预算都会影响版本。`catalogue` 仅列主题、位置、关系和缺口，
   不把各卡正文一次倒出。
4. `read_cards` 对 `corrects` / `updates` / `conflicts` 求必要关联闭包。
   点旧安排会同时带上后续取消；若必要卡被暂扣，或整组超出交付预算，整组暂扣并报告原因。
   不在预算不足时只留下旧计划。连带卡上的其他必要关系也继续纳入，仍受整包预算限制。
5. `expand` 根据事实、未知或关系编号返回逐字原文、位置及记录指纹，区分当前与历史引用。
   目录、选卡、展开均校验整个当前来源窗口及来源/房间/分支；窗口追加后续记录也使旧稿失效。
   返回值与核验档案分离，调用方修改展示内容不能就地改写档案。

仅支持 `synthetic` 身份。现有窗口上限是 64 条、24,000 字符；作者稿最多 32 个事件、
每事件 24 项事实、合计 128 项，整稿最多 256,000 字节。单卡预算可设 512–64,000 字节，
默认 4,096；交付预算单独计算。这里是有界原型，不是无限容量或全库分段器。

作者未处理完须标 `partial` 并列出来源缺口；`layout_complete` 只表示作者交来的事件能装下。
未引用记录/片段是遗漏排查线索，并不证明引用过的内容已完整、关系正确或摘要忠实。
作者未声明的遗漏仍可能存在，不能用 `ok` 或“排版完成”替代语义复核。

## 本地验证结果

`scripts/summary_event_booklet_trial.py` 只使用明确手写注入的结构样本，没有模型生成器，
不是新一轮模型考试，也不用于计算自然生活资料的压缩收益。

| 结构样本 | 提供的内容 | 分卡结果 | 检查结果 |
|---|---|---|---|
| 容量与末尾保留 | 30 条合成记录、30 个事件、32 项事实 | 5 张卡；每卡上限 1,800 字节，最大 1,717 | 32 项全部可回查，末尾称呼、感受和待办保留 |
| 旧安排与后续取消 | 5 条合成记录、3 个事件、3 项事实 | 3 张卡；每卡上限 800 字节，最大 643 | 请求 c1，实际同时交付 c1 与 c3 |

容量样本前 27 项故意重复构造负载，只证明不会在第 24 项之后截断。
关系样本故意把旧计划和取消分开，验证跨卡保护，不主张这种拆法是最佳摘要组织方式。
两份样本共 35 项事实逐字回查通过；目录分别为 3,293 和 1,029 字节。
所有结果保持 `semantic_passed=null`、`production_accepted=false`。

相关检查 **136 项通过**，包括完整事件容量边界、整体超限、更新链、原文追加导致失效、
错房/错分支、展示篡改、当前与历史出处、中文/组合字符/换行、作者未声明遗漏和返回值隔离。
现有 Chroma 依赖有一条弃用提醒；本次未改变该依赖。

Windows 执行检查时启用 UTF-8；否则现有摘要柜的子进程输出测试会遇到系统默认编码不匹配：

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
python -m pytest tests/test_summary_event_booklet.py tests/test_summary_reading_card.py tests/test_summary_faithfulness.py tests/test_summary_isolated_trial.py tests/test_summary_cabinet.py -q
python scripts/summary_event_booklet_trial.py
```

可选 `--output-dir` 写入新的本地试验目录，已有目录拒绝覆盖。
本轮演示档案保存在 Git 忽略的 `.tmp/summary-event-booklet-20261125-v2/`；旧版也保留。
本轮模型调用为 0，新增 API 费用为 0。
