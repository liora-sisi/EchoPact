## 两步各自做什么

`backend/memory/semantic_shortlist.py` 的 `ShortlistBridge` 复用前两节接头：

```text
完整原候选卡（本机审计保留）
  → 第一次模型：只分 inspect / defer / discard，不写答案或引文
  → 本机：保留被圈中记录的全部已有窗口，补已知冲突方
  → 本机：按原始分支位置回取附近消息，整组装包
  → 第二次模型：复用原有顺序证据筛选
  → 本机：逐字引文、来源、当前权限、容量及缺口复核
  → 有界证据包，仍需正式验收
```

- 第一阶段每个临时卡号恰好分类一次，最多选两张卡；有价值却暂时放不下的线索必须列入 `defer`。
  `discard` 也是模型判断，不是本机确认无用。全部不选时仍保留原包，不能宣称历史上没有答案。
- 一条长消息被圈中任何一个窗口，该记录原先找到的其他窗口仍保留。
  不能初选旧说法后，把同消息里的更正窗口当作落选片段删除。
- 已有明确冲突组自动补齐；闭包超过两条根记录时回原包，不用圈选偷藏冲突方。
- 最多两次模型调用，无自动重试或补查循环。第一阶段完全没有事实输出字段。
  第二阶段不生成自由回答，仍只选连续原文，附本机来源与附近语境。
- 初选明确延后的线索计数传入最终包，强制 `needs_more_evidence=true`；不让第二阶段只看局部后
  声称整题已经补齐。`model_sufficiency` 仅是第二阶段可见摘录的模型判断。
- 首次失败、无圈选、冲突/邻文超限或第二阶段失败时保留完整原种子审计，并退回原未审预览。
  缺少第二阶段回调时只能标为 `shortlisted_context_unreviewed`。
- 每一阶段前后复核冻结原库及当前身份。第一阶段丢弃的原候选仍在权限与源库变化检查范围内。

新代码没有数据库写入或网络客户端；模型通过两个显式回调注入。
`semantic_shortlist_trial.py` 只为显式虚构试验复用现有 provider 传输，不改变生产配置。

## 上限与额外开销

每次数据请求仍至多十二张卡、每卡四百字符、24,000 UTF-8 字节；
最终包仍为 12,000 字节。最多两条根记录不等于整个证据包只有两条消息：
其已有窗口与可见邻文一起受原有组上限约束。

**本节多了一次初选调用**，两次数据请求合计上限为 48,000 字节。
不能把每次仍为 24 KB 描述为总输入没有增加；系统提示与 schema 也会产生用量，
费用预留按实际 API payload 计算。第一阶段最多 768 输出 token，第二阶段沿用原 1,800。

## 首次实际模型验收

固定虚构卷 `tests/fixtures/semantic_shortlist_exam.json` 在调用前冻结原文、问句、
原候选位置、预期证据和实现。原候选/偏移是组件输入，**不是一次新的向量检索成绩**。
第二阶段请求由固定虚构库和已验证初选结果推导，发送前重新核验来源白名单并单独落档。
两个阶段都不接收评判标签、真实私人材料或任意外部语料。

| 题型 | 第一次实际结果 |
|---|---|
| 十张卡的第八张才含有效旧说法 | 初选 `c8`，补邻文后选更正用途；排除指令注入卡 |
| 一条长消息两个窗口，下一条补条件 | 两窗口同属一条根记录，保留更正与限制条件 |
| 最初只有未定方案，附近有两个分支决定 | 仍愿意补查；保留两个分支的矛盾，不擅选一个 |
| 原位置后来撤回，尚无新位置 | 保留撤回证据并报缺答案，不沿用旧位置 |
| 三件明确相关物品，但初选只容两张 | 另一张列入 `defer`，最终仅给部分证据并报缺口 |

五题各两次 GPT-5.6 调用，合计十次，首次 **5/5**。
没有修改提示重考，没有把本地重放算成新的模型成绩，也未调用接收方模型生成自由回答。
逐项核对原句，否定、对象、条件和分支冲突均保留。

实际数据请求两步合计 **662–3,500 字节**，最终包 **2,157–3,802 字节**。
这些大小不包含系统提示和 schema；带出处的最终包也不一定比输入卡更小。
第八张题还保留了两张待查线索，不能因本轮已找到目标就把其缺口计数清零。
